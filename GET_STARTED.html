u-maker 시작하기

0 u-maker가 뭔가요?

u-maker는 Claude Code 플러그인으로, 소프트웨어 개발의 전 과정을 자동화해주는 도구입니다.

쉽게 말하면, 7명의 AI 전문가 팀이 여러분의 프로젝트를 함께 만들어줍니다. 이 팀이 Plan → Design → Do → Check → Act 사이클(PDCA)을 돌면서 프로젝트를 완성합니다.

각 Phase별 활동하는 에이전트

1 설치하기

필요한 것들: Claude Code (필수), Node.js (스크립트 실행), bun (빌드/실행)

1 배포 스크립트 실행

u-maker-plugin 폴더에서 배포 스크립트를 실행합니다.

cd /path/to/u-maker-plugin
./deploy_local.sh

2 설치 확인

설치가 잘 되었는지 확인하고, Claude Code를 재시작합니다.

./deploy_local.sh --check
# Claude Code 재시작 후
/u-skill-help

2 프로젝트 시작하기

A 새 프로젝트 만들기

처음부터 새로 시작할 때. Turborepo + SSoT 문서 구조가 자동 생성됩니다.

/u-skill-create-project my-app

B 기존 프로젝트에 적용

이미 있는 프로젝트에 u-maker를 적용할 때. 코드를 분석해서 SSoT 문서를 역공학 생성합니다.

/u-skill-init .

3 개발 시작하기

프로젝트가 준비되었으면, 가장 쉬운 방법은 자동 루프입니다. 이 한 줄이면 Plan → Design → Do → Check → Act 전체 사이클을 자동으로 돌립니다.

/u-skill-loop

단계별로 직접 실행하고 싶다면:

순서Phase명령어설명
1Plan/u-skill-plan로드맵, SRS, IA, 인덱스 생성
2Design/u-skill-design화면 설계, ERD, API, UX 가이드
3Do/u-skill-devFE/BE 코드 구현
4Check/u-skill-check테스트 케이스 설계 & 실행
5Act/u-skill-act백로그 정리, 회고, 아카이브
 
flowchart TD
    PLAN["PLAN<br/>기획"] -->|Gate| DESIGN["DESIGN<br/>설계"]
    DESIGN -->|Gate| DO["DO<br/>구현"]
    DO --> GAP{"Gap Check<br/>Match >= 90%?"}
    GAP -->|No| INNER["Inner Gap Loop<br/>Gap FT별 재실행"]
    INNER --> GAP
    GAP -->|Yes| CHECK["CHECK<br/>검증"]
    CHECK --> EXIT{"Exit Criteria<br/>충족?"}
    EXIT -->|Yes| COMPLETE["COMPLETE<br/>+ Loop Report"]
    EXIT -->|No| ACT["ACT<br/>개선"]
    ACT -->|Next Iteration| PLAN
PDCA 자동 루프 흐름도 — Gap Check와 Exit Criteria를 자동 판정합니다

5 핵심 개념 이해하기

📚 SSoT (Single Source of Truth)

u-maker는 "문서가 곧 진실" 원칙으로 동작합니다.

모든 요구사항, 설계, 구현 기록이 .u-maker/docs/에 문서로 관리됩니다. 문서를 먼저 작성하고, 그 문서를 기반으로 코드를 생성합니다.

코드만 먼저 작성하려 하면 Docs-First Guard가 막고, 문서를 먼저 쓰라고 안내합니다.

🔄 PDCA 사이클

각 Phase를 넘어가려면 Gate 조건을 충족해야 합니다. 예를 들어 Plan의 문서가 Final 상태가 되어야 Design으로 넘어갈 수 있습니다.

PhaseAgents주요 활동Gate 조건
PLANPM, SA, UXRoadmap, SRS, IA, IndexRoadmap + SRS + IA = Final
DESIGNUX, SA, RAUXGuide, Screen, ERD, API, RTMERD + RTM + API + Screen = Final
DOUX, DV-FE, DV-BEFrontend, Backend, Code DocBuild OK + Match Rate ≥ 90%
CHECKQATC 설계, 실행, 결함 분석Critical/Major = 0, All FT Done
ACTRA, PMBacklog, Archive, RetrospectiveLog + Retro 완료

🔗 4-Tier ID 체계

요구사항부터 구현까지 추적할 수 있는 계층 구조입니다. "이 코드가 왜 존재하는지"를 항상 추적할 수 있습니다.

flowchart TD
    USR["USR-XXXX<br/>User Type<br/><i>관리자, 일반 사용자</i>"]
    FR["FR-XXXX<br/>Functional Req.<br/><i>고객 요구사항</i>"]
    US["US-XXXX<br/>User Story<br/><i>사용자 관점으로 분해</i>"]
    FT["FT-XXXX<br/>Feature ★<br/><i>구현 추적 기본 단위</i>"]
    USR --> FR --> US --> FT
4-Tier ID Hierarchy — USR → FR → US → FT
flowchart LR
    FR[FR] --> US[US] --> FT[FT] --> Screen[Screen] --> API[API Endpoint] --> DB[DB Entity] --> TC[Test Case]
요구사항 추적표(RTM) — FR부터 TC까지 전 구간 추적

📝 문서 산출 파이프라인

u-maker는 정해진 순서대로 문서를 생성합니다. 각 문서는 이전 문서를 기반으로 작성됩니다.

flowchart LR
    SRS["SRS<br/>FR→US→FT"] --> IA["IA<br/>정보 구조도"]
    IA --> UXGuide["UXGuide<br/>디자인 시스템"]
    UXGuide --> Screen["Screen<br/>화면 설계"]
    Screen --> ScreenFlow["ScreenFlow<br/>화면 흐름도"]
    ScreenFlow --> Wireframe["Wireframe<br/>HTML"]
    Wireframe --> Design["Design<br/>.pen"]
    Design --> ERD[ERD]
    ERD --> API["API Contract"]
    API --> Dev["Dev<br/>FE + BE"]
    Dev --> Test[Test]
문서 산출 순서 — SRS부터 Test까지

6 문서 구조 한눈에 보기

.u-maker/docs/ ├── common/ # 프로젝트 전체 공용 │ ├── 01-plan/ # Roadmap, Index, Common │ ├── 02-design/ # ERD, UX Guide, RTM │ ├── 03-dev/ # UI Components, Design Token │ └── 05-act/ # Retrospective, Reports, Backlog ├── {app}/ # 앱별 문서 (예: web, admin) │ ├── 01-plan/ # SRS (요구사항 명세), IA (정보 구조도) │ ├── 02-design/ # API 설계, Screen 설계, Wireframe │ ├── 03-dev/ # 구현 기록 │ └── 04-check/ # Test Cases, QA Report └── iterations/ # 지난 Iteration 아카이브 └── iter-N/

3-File Export Rule: 모든 SSoT 문서는 생성/갱신 시 .md + .json 2종 파일을 동시 생성합니다. 리포트 문서는 .html까지 3종 파일을 생성합니다.

8 자주 묻는 질문

명령어가 안 보여요

1. ./deploy_local.sh --check로 설치 상태를 확인하세요
2. Claude Code를 재시작하세요
3. /u-skill-help를 입력해 명령어 목록이 나오는지 확인하세요

"문서를 먼저 업데이트하세요"라는 메시지가 뜹니다

u-maker의 Docs-First 원칙 때문입니다. 새 기능을 코드로 바로 구현하려 하면 이 메시지가 나옵니다.

# 먼저 문서를 추가한 후
/u-skill-us-add
/u-skill-fr-add web

# 그 다음에 구현을 진행하세요
/u-skill-dev web
루프가 계속 돌아요

기본적으로 최대 10회까지 반복되며, 이후 자동 종료됩니다.
바로 멈추고 싶으면 /u-skill-stop을 사용하세요.

멀티앱 프로젝트는 어떻게 하나요?

앱 이름을 인자로 전달하면 됩니다:

/u-skill-plan web # web 앱에 대한 Plan
/u-skill-design admin # admin 앱에 대한 Design
/u-skill-dev web # web 앱 개발
자연어로도 요청할 수 있나요?

네! 슬래시 명령어 대신 자연어로 말해도 u-maker가 알아서 적절한 에이전트로 라우팅합니다:

"로그인 기능을 추가하고 싶어" → RA/SA 에이전트가 문서 작성
"ERD를 PostgreSQL로 최적화해줘" → SA 에이전트가 ERD 수정
"테스트 케이스를 보강해줘" → QA 에이전트가 TC 추가

TL;DR — 3줄 요약

1. 설치: ./deploy_local.sh 실행 후 Claude Code 재시작
2. 프로젝트 생성: /u-skill-create-project my-app (새 프로젝트) 또는 /u-skill-init . (기존 프로젝트)
