# 회의록 품질 평가 기준 (10개 항목)

Minutes Reviewer 에이전트가 생성된 HTML 회의록을 평가할 때 사용하는 상세 채점 기준.
각 항목은 0~100점으로 채점하며, 10개 항목의 **산술 평균이 95점 이상**이면 합격.

---

## 1. 구조 완전성 (Structure Completeness)

7개 필수 섹션과 모든 구조 요소가 빠짐없이 포함되어 있는지 평가.

**필수 섹션 체크리스트:**
- `<!DOCTYPE html>`, `<html lang="ko">`, `<head>` 메타 태그, Pretendard CDN
- 전체 CSS 인라인 포함 (`<style>` 태그 내)
- `.layout` > `.sidebar` + `.main-content` 구조
- 사이드바: `.sidebar-header`, `.sidebar-nav`, `.sidebar-footer`
- 회의 메타정보 카드: `.meeting-info` + `.meeting-info-grid`
- **01. 개요** (`#overview`): `.highlight-box`로 핵심 요약
- **02. 참석자 & 안건** (`#attendees`): 화자 추론 테이블 + 회의 타임라인
- **03. 논의 내용** (`#discussion`): `.feature-cards`
- **04. 결정 사항** (`#decisions`): `.decision-list`
- **05. 액션 아이템** (`#actions`): `.data-table`
- **06. AI 커멘트** (`#ai-comments`): `.ai-comment-list`
- **07. 다이어그램** (`#diagrams`): `.diagram-card` (해당 내용 있을 때)
- `#scrollTopBtn` 스크롤 투 탑 버튼
- 사이드바 활성 추적 JavaScript

**채점 기준:**
| 점수 | 조건 |
|------|------|
| 100 | 모든 필수 섹션·요소 포함, 순서와 계층 정확 |
| 95 | 필수 섹션 모두 있으나 사소한 순서 문제 (예: sidebar-footer 누락) |
| 90 | 1개 부수 요소 누락 (예: 타임라인) |
| 80 | 1개 핵심 섹션 누락 (예: AI 커멘트) |
| 60 이하 | 2개 이상 핵심 섹션 누락 |

## 2. 디자인 시스템 준수 (Design System Compliance)

`assets/template.html`의 CSS 변수와 클래스를 정확하게 사용하는지 평가.

**체크 포인트:**
- `:root` CSS 변수 정의가 template.html과 일치 (다크 사이드바: `--sidebar-bg: #1e2432`)
- `.sidebar`, `.meeting-info`, `.feature-card`, `.decision-list`, `.ai-comment-card` 등 정의된 클래스 사용
- 임의의 인라인 스타일 최소화
- 색상 팔레트: `--accent`, `--green`, `--red`, `--yellow`, `--purple`, `--gray` 계열만 사용
- 카드 variant: `.feature-card.green/.purple/.yellow/.red`, `.ai-comment-card.suggestion/.warning/.risk`

**채점 기준:**
| 점수 | 조건 |
|------|------|
| 100 | 모든 스타일이 디자인 시스템과 100% 일치 |
| 95 | 1-2곳 사소한 불일치 (여백, 패딩 정도) |
| 90 | 정의되지 않은 인라인 스타일 3개 이상 사용 |
| 80 | 디자인 시스템 외 색상/폰트 사용 |
| 70 이하 | CSS 변수 미사용, 하드코딩 다수 |

---

## 3. 콘텐츠 정확성 (Content Accuracy)

원본 트랜스크립트의 내용이 회의록에 정확하게 반영되었는지 평가.

**체크 포인트:**
- 원본 트랜스크립트의 모든 주요 논의 포인트가 회의록에 포함 (누락 없음)
- 숫자, 날짜, 이름 등 팩트 데이터가 정확
- 발언 내용이 왜곡·과장되지 않음
- 원본에 없는 내용을 임의로 추가하지 않음
- 구어체가 적절하게 문어체로 변환됨 (의미 보존)
- 화자의 발언이 다른 화자에게 잘못 귀속되지 않음

**채점 기준:**
| 점수 | 조건 |
|------|------|
| 100 | 원본 대비 100% 정확 반영, 누락 없음 |
| 95 | 1-2건 사소한 표기 차이 |
| 90 | 3-5건 논의 포인트 누락 또는 부정확 |
| 80 | 주요 논의 주제 1개 이상 누락 |
| 60 이하 | 다수 내용 오류 또는 왜곡 |

---

## 4. 화자 추적 정확성 (Speaker Attribution Accuracy)

화자 라벨이 일관되고, 화자 추론 테이블이 정확한지 평가.

**체크 포인트:**
- 화자 라벨이 `참여자1`, `참여자2`, ... `참여자N` 형식으로 통일
- 본문(논의, 결정, 액션)에서 실명이 직접 사용되지 않음 (참여자N만 사용)
- 화자 추론 테이블: 화자/추론 이름·역할/확신도 3컬럼만 (근거 컬럼 없음)
- 확신도: `확인`(badge-green) 또는 `추정`(badge-purple) 적절 사용
- 같은 화자의 발언이 일관된 라벨로 귀속
- `.txt` 파일의 `Attendees N` → `참여자N` 매핑 정확

**채점 기준:**
| 점수 | 조건 |
|------|------|
| 100 | 라벨 완벽 통일, 추론 테이블 정확, 근거 컬럼 없음 |
| 95 | 1곳 라벨 불일치 또는 확신도 부적절 |
| 90 | 본문에 실명이 직접 사용된 곳 1-2곳 |
| 80 | 화자 추론 테이블에 근거 컬럼 포함 또는 라벨 혼재 |
| 70 이하 | 화자 라벨 체계 미준수, 귀속 오류 다수 |

---

## 5. 논의 구조화 (Discussion Structuring)

논의 내용이 주제별로 적절하게 구조화되고, 화자 turn이 추적되는지 평가.

**체크 포인트:**
- 논의 내용이 feature-card로 주제별 그룹핑
- 각 카드에 주제 뱃지와 border-left 색상으로 시각 구분
- 화자별 주장/질문/반박이 분리되어 기록
- 같은 화자의 연속 발화가 하나의 문맥 단위 turn으로 통합
- 시간순이 아닌 주제순 정리 (맥락상 자연스러운 경우)
- `.annotation`으로 각 주제의 배경·맥락 첨부

**채점 기준:**
| 점수 | 조건 |
|------|------|
| 100 | 모든 논의가 주제별로 명확히 구조화, 화자 turn 추적 완벽 |
| 95 | 대부분 좋으나 1-2 주제에서 화자 구분 불명확 |
| 90 | 일부 주제가 flat한 리스트로만 나열 |
| 80 | 주제 구분 없이 시간순 나열, feature-card 미사용 |
| 70 이하 | 논의 내용 구조화 미흡 |

---

## 6. 결정/액션 분리 (Decision & Action Clarity)

결정 사항과 액션 아이템이 명확하게 분리되고 구체적인지 평가.

**체크 포인트:**
- 결정 사항: 회의에서 합의/확정된 내용만 포함
- 결정 사항은 `.decision-list` 카드 형태로 표시
- 액션 아이템: `#`, 항목, 담당(참여자N), 상태를 `.data-table`로 표기
- 결정과 액션이 혼재되지 않음 (결정 ≠ 액션)
- 각 결정/액션에 `.annotation`으로 맥락 첨부 (해당 시)
- 액션 아이템의 담당자가 명확하고, 상태 뱃지 적절

**채점 기준:**
| 점수 | 조건 |
|------|------|
| 100 | 결정/액션 완벽 분리, 구체적, 담당자·상태 명확 |
| 95 | 1건 결정과 액션 구분 모호 |
| 90 | 액션 아이템에 담당자 또는 상태 누락 2건 이상 |
| 80 | 결정/액션 혼재, 구분 기준 불명확 |
| 70 이하 | 결정 사항과 액션 아이템이 분리되지 않음 |

---

## 7. 네비게이션 기능성 (Navigation Functionality)

사이드바 네비게이션, 앵커 링크, 스크롤 추적이 정확히 동작하는지 평가.

**체크 포인트:**
- 사이드바 `<a href="#sectionId">`와 본문 `.section-divider[id]` 일치
- 모든 `.section-divider`에 고유한 `id` 속성 존재
- 사이드바 항목 수 = 본문 섹션 수 일치
- `.nav-icon` 번호가 01, 02, ... 순차적
- 스크롤 추적 JavaScript가 `sections`과 `navLinks`를 올바르게 참조
- `scrollTopBtn` 동작 코드 포함

**채점 기준:**
| 점수 | 조건 |
|------|------|
| 100 | 모든 링크 정확, 스크롤 추적 완벽 |
| 95 | 1개 링크 id 불일치 |
| 90 | 사이드바 번호 순서 오류 |
| 80 | 사이드바 항목과 본문 섹션 수 불일치 |
| 70 이하 | 네비게이션 깨짐 또는 JavaScript 미포함 |

---

## 8. AI 분석 품질 (AI Analysis Quality)

AI 커멘트 섹션이 통찰력 있고, 단순 반복이 아닌 분석적인지 평가.

**체크 포인트:**
- `.ai-comment-card.warning`: 회의에서 논의가 부족하거나 빠진 부분 식별
- `.ai-comment-card.risk`: 잠재적 리스크나 미결정의 영향 분석
- `.ai-comment-card.suggestion`: 구체적 개선 방향 제안
- 커멘트가 회의 내용에 기반한 구체적 분석 (일반론 금지)
- 각 커멘트에 `.annotation`으로 근거 발언이나 맥락 첨부
- 최소 2개 이상의 AI 커멘트 포함

**채점 기준:**
| 점수 | 조건 |
|------|------|
| 100 | 통찰력 있는 분석, 구체적 근거, 실행 가능한 제안 |
| 95 | 대부분 좋으나 1개 커멘트가 다소 일반적 |
| 90 | AI 커멘트가 1개뿐이거나 깊이 부족 |
| 80 | 일반론 수준의 커멘트, 회의 내용과 연결 약함 |
| 70 이하 | AI 커멘트 섹션 없음 또는 무의미 |

---

## 9. 다이어그램 적합성 (Diagram Relevance & Quality)

SVG 다이어그램이 회의 내용과 관련 있고 기술적으로 정확한지 평가.

**체크 포인트:**
- 다이어그램이 회의에서 논의된 실제 프로세스/구조를 시각화
- SVG가 인라인으로 `.diagram-card` 안에 삽입
- `viewBox` 속성으로 반응형 처리, `width`/`height` 직접 지정 없음
- 색상이 회의록 CSS 변수와 일치 (`#4f8cff`, `#22c55e` 등)
- 폰트: `Pretendard, -apple-system, sans-serif`
- 고유 ID prefix로 SVG ID 충돌 방지
- 다이어그램이 없을 정당한 이유가 있으면 (시각화할 내용 없음) 감점하지 않음

**채점 기준:**
| 점수 | 조건 |
|------|------|
| 100 | 관련성 높고 기술적으로 정확한 다이어그램 |
| 95 | 다이어그램 있으나 색상 또는 폰트 1-2곳 불일치 |
| 90 | 다이어그램이 회의 내용과 관련성이 낮음 |
| 85 | 시각화할 내용이 명확히 있는데 다이어그램 누락 |
| N/A | 시각화할 내용 없음 → 이 항목 제외하고 9개 평균 |

---

## 10. 완성도 (Completeness & Polish)

빈 섹션, TODO, 플레이스홀더 없이 완전히 마감되었는지 평가.

**체크 포인트:**
- `TODO`, `FIXME`, `XXX`, `{{placeholder}}` 등 미완성 마커 없음
- 빈 `<td>`, 빈 `<li>`, 빈 섹션 없음 (빈 값은 `&mdash;` 처리)
- `Lorem ipsum` 등 더미 텍스트 없음
- 모든 `.badge` 색상이 의미적으로 적절
- `.nav-icon` 번호가 순차적이고 정확
- 일관된 문체 (존댓말/평어 통일)
- 구어체가 문어체로 적절히 변환
- HTML 엔티티 올바르게 이스케이프 (`&amp;`, `&lt;` 등)
- 코드 들여쓰기 일관

**채점 기준:**
| 점수 | 조건 |
|------|------|
| 100 | 완벽한 마감, TODO/빈 섹션 없음, 일관된 문체 |
| 95 | 1-2건 사소한 미완성 (뱃지 색상 등) |
| 90 | 빈 셀 3-5개 `&mdash;` 미처리 |
| 80 | TODO 또는 플레이스홀더 존재 |
| 60 이하 | 다수 미완성 영역 |

## Reviewer 출력 형식 (필수)

평가 결과는 반드시 아래 형식을 따른다:

```markdown
## 평가 결과

| # | 기준 | 점수 | 비고 |
|---|------|------|------|
| 1 | 구조 완전성 | XX | 간단한 평가 코멘트 |
| 2 | 디자인 시스템 준수 | XX | ... |
| 3 | 콘텐츠 정확성 | XX | ... |
| 4 | 화자 추적 정확성 | XX | ... |
| 5 | 논의 구조화 | XX | ... |
| 6 | 결정/액션 분리 | XX | ... |
| 7 | 네비게이션 기능성 | XX | ... |
| 8 | AI 분석 품질 | XX | ... |
| 9 | 다이어그램 적합성 | XX | ... |
| 10 | 완성도 | XX | ... |

**평균 점수: XX.X / 100**
**합격 여부: PASS / FAIL**

## 개선 피드백 (95점 미만 항목)

### [기준명] (현재 XX점 → 목표 95+)
- 문제 1: [구체적 위치와 내용]
- 개선 방안: [어떻게 수정해야 하는지]
- 문제 2: ...
- 개선 방안: ...
```

**주의사항:**
- 점수는 정수로 부여 (소수점 없음)
- 평균은 소수점 첫째 자리까지 표시
- 다이어그램 적합성이 N/A이면 9개 평균으로 계산
- 95점 이상 항목에는 개선 피드백을 작성하지 않음
- 감점 사유는 구체적으로 (몇 번째 섹션의 어떤 요소인지 명시)
- 단순히 "좋음" / "부족함" 같은 모호한 평가 금지
