# 회의록 품질 평가 기준 (모드별 10개 항목)

Minutes Reviewer 에이전트가 생성된 HTML 을 평가할 때 사용하는 채점 기준.
**해당 모드의 섹션만 적용**한다. 각 항목 0~100점, 10개 항목의 **산술 평균 95점 이상**이면 합격.

공통 채점 스케일 (각 기준의 세부 체크 포인트에 대해):

| 점수 | 조건 |
|------|------|
| 100 | 체크 포인트 전부 충족, 결함 없음 |
| 95 | 사소한 결함 1~2건 (표기·여백 수준) |
| 90 | 부수 요소 누락 또는 부정확 1건 |
| 80 | 핵심 요소 누락·오류 1건 |
| 70 이하 | 핵심 요소 누락·오류 2건 이상 |

---

# §A — Mode A 일반 회의록

## A1. 구조 완전성
- `<!DOCTYPE html>`, `<html lang="ko">`, **Font Awesome CDN**(head `<link>`) — 웹폰트 CDN 없이 시스템 서체 스택, 전체 CSS 인라인
- `.progress-bar` + `.layout` > `.sidebar`(좌 네비) + `.main-content` + **`.glance`(우 한눈 요약 레일)** 구조
- 좌 사이드바: header / nav(+`nav-count`) / footer
- **우 글랜스 레일 필수**: `.glance-head` + 4블록(요약 `.glance-summary` / 결정사항→`#decisions` / 미결사항→`#open-issues` / 액션→`#actions`). 블록 아이콘은 **Font Awesome**(`fa-thumbtack`/`fa-circle-check`/`fa-hourglass-half`/`fa-list-check`, 이모지 금지), 결정/미결/액션 제목은 본문 앵커, `.gb-count` = 실제 수
- `.meeting-info` + `.meeting-info-grid` + **`.stat-row` 통계 칩**
- 7개 섹션: `#overview`(highlight-box) → `#attendees`(화자 추론 테이블+타임라인) → `#discussion`(feature-cards) → `#decisions`(decision-list) → **`#open-issues`(issue-list — 미결 사항)** → `#actions`(data-table) → `#ai-comments`(ai-comment-list)
- 다이어그램은 별도 섹션 아님 — 본문 인라인 (A9)
- `.float-tools` (glanceToggle + widthToggle + scrollTopBtn) + 스크립트 5종 (진행률·스크롤탑·폭토글·**글랜스토글**·활성추적)

## A2. 디자인 시스템 준수
- `:root` 변수·클래스가 `template-general.html` 과 일치, 임의 인라인 스타일 최소화
- 정의된 팔레트만 사용, 카드 variant 정확
- **아이콘 = Font Awesome (하드 룰)**: UI 아이콘은 `<i class="fa-solid fa-…">`, **이모티콘(📌✅⏳📋 등) 사용 시 감점**. 장식 아이콘 `aria-hidden`, 의미 아이콘엔 인접 텍스트
- **한쪽 border accent 금지 (하드 룰)**: `feature-card`·`highlight-box`·`ai-comment-card`·`annotation`·`quote`·`stat` 은 전체 `border` + 옅은 배경. `border-left: Npx solid …` 강조 잔존 시 감점 (섹션 제목 밑줄·사이드바 active·테이블 행 구분선은 예외)

## A3. 콘텐츠 정확성
- 원본 전사의 모든 주요 논의 포인트 반영 (누락 없음), 숫자·날짜·이름 정확
- 발언 왜곡·과장 없음, 원본에 없는 내용 창작 없음
- 구어체 → **간결한 평이체** 변환이 의미 보존 (문어체지만 짧게 — A5 참조)
- whisper 환각 반복 블록이 내용에 유입되지 않음

## A4. 화자 추적 정확성
- 본문 화자 라벨 `참여자N` 통일 + `.sp .sN` 색상 칩 일관 사용 (같은 참여자 = 같은 번호·색)
- 본문 실명 직접 사용 없음, 실명은 화자 추론 테이블만 (3컬럼, 근거 컬럼 없음)
- 확신도 `확인`(badge-green)/`추정`(badge-purple) 적절

## A5. 논의 구조화 & 간결성
- feature-card 주제별 그룹핑, 화자별 주장/질문/반박 분리, 연속 발화 turn 통합
- **간결·평이 (하드 룰, 중학생 이해 수준)**: 개조식(bullet) 우선, 한 항목 1~2줄. 논문투·장문·과한 명사화·수동태 금지, 쉬운 말. 설명 문장은 중학생이 처음 읽어도 이해되게 — 전문용어·약어는 첫 등장에서 괄호 한 줄 풀이, 풀이 없는 약어 잔존 시 감점. 3줄 초과 산문 문단이 카드를 덮으면 감점 (독자가 "논문 같다" 고 느끼는 원인). 규칙 원문: u-engine `html-engine.md` §0.6 / `doc-engine.md` §8 (GK-06 `plain-language-middle-school` 검사와 동일 기준)
- `.quote` 는 결정적 발언에만 (카드당 ≤1, 전체 3~6개) + 발화자·시각 표기
- `.topic-meta` 로 논의 구간 타임스탬프 표기, `.annotation` 으로 배경 첨부
- 곁가지 논의는 누락 대신 `details.collapse` 처리

## A6. 결정/미결/액션 분리
- 결정 = 합의·확정만 (`decision-list` + `decision-tag` agree/hold/cond 적절)
- **미결 = 아직 안 정한 것** (`#open-issues` `.issue-list`) — 결정으로 위장 금지, 글랜스 미결 블록과 일치
- 액션 테이블: #/항목/담당(참여자N)/기한/상태 — 기한 미언급 시 `&mdash;`, 상태 뱃지 의미 적절
- 결정·미결·액션 혼재 없음

## A7. 네비게이션·인터랙션 기능성
- 사이드바 href ↔ `.section-divider[id]` 전부 일치 (7섹션), `nav-icon` 순차, `nav-count` 실제 수와 일치
- **글랜스 레일**: 결정/미결/액션 블록 제목 앵커가 본문 섹션으로 이동, `.gb-count` = 실제 수
- 진행률 바·폭 토글(780↔1100)·**글랜스 토글**·스크롤 탑·활성 추적 스크립트 동작 (요소 id 정확)

## A8. AI 분석 품질
- warning(누락 논의) / risk(리스크) / suggestion(개선) 유형별 최소 1개, 총 2개 이상
- 일반론 금지 — 회의 내용 기반 구체 분석 + `.annotation` 근거

## A9. 다이어그램 적합성
- 시각화 가능한 프로세스·구조·관계·플로우가 논의됐으면 **필수** — 관련 카드 바로 아래 `.diagram-card` 인라인
- 별도 섹션으로 분리 시 80점 이하, 시각화 가능한데 누락 시 70점
- 인라인 SVG (Mermaid 금지), viewBox 반응형, 팔레트·폰트 준수, ID prefix 고유
- 시각화할 내용이 전혀 없으면 N/A → 9개 평균

## A10. 완성도
- `TODO`/`{{placeholder}}`/빈 섹션·빈 셀 없음 (빈 값 `&mdash;`), stat-row 숫자가 본문 실제 개수와 일치
- 문체 일관, HTML 엔티티 이스케이프, 뱃지 색 의미 적절

# §B — Mode B 리뷰 회의록

## B1. 항목 완전성 (누락 제로)
- 전사의 **모든 수정 지시가 항목화** — 원본 대조로 누락 검증 (가장 중요한 기준)
- 중복 언급은 1개 항목으로 병합, 항목 창작 없음
- 팀 합의사항은 약속·규칙 섹션에 분리 수록

## B2. 3단 구조 품질 (지금/할 일/확인)
- 전 항목에 3행 존재, 각 1~2문장
- **지금** = 관찰 가능한 현상 / **할 일** = 실행 가능한 작업 / **확인** = O/X 판정 가능한 검수 기준
- "정상 동작하면 됩니다" 류의 판정 불가 확인 문구는 감점

## B3. 뱃지·우선순위 정확성
- 유형 판정이 design-system-review.md 기준표와 일치 (버그=불능/수정=개선/연동=데이터연결/정책=기준결정)
- 항목당 유형 뱃지 1개, `먼저!` 병기 적절 (흐름 차단 버그 또는 명시적 우선 지목)
- `data-type`·`data-first` 가 표시 뱃지와 전부 일치 (필터 정합성)
- P0 목록 = `먼저!` 항목 전체와 일치

## B4. 타임스탬프 정확성
- 전 항목·캡쳐에 `⏱ H:MM:SS` — 스크립트 대조 시 해당 논의 시각과 일치 (±1분 허용)
- 세션 분할 회의에서 video_offset 매핑 오류 없음

## B5. 화면 캡쳐 적합성
- P0 전건 + 시각적 항목에 캡쳐 존재, 캡쳐가 항목 내용과 실제로 관련된 화면
- base64 인라인 (외부 참조 0), 크롭이 공유 화면 영역을 정확히 담음 (참가자 타일·검은 여백 잔존 감점)
- figcaption: `<b>라벨</b> 설명 + ⏱` 형식, 라벨 ASCII

## B6. 쉬운 언어 (설명판 품질)
- **중학생·비개발자가 처음 읽어도 이해 가능 (하드 룰)** — 짧은 문장·쉬운 낱말, 전문용어·약어는 첫 등장에서 괄호 한 줄 풀이, ID·수치는 그대로. 규칙 원문: u-engine `html-engine.md` §0.6 / `doc-engine.md` §8 (GK-06 `plain-language-middle-school` 검사와 동일 기준)
- 항목 제목은 현상 중심 한 줄, 존댓말 평서형 통일
- 읽는 법(30초) 섹션이 실제 문서 규칙과 일치

## B7. 구조·네비게이션
- 문서 순서: hero → legend → sticky-nav → p0 → toc → 약속·규칙 → 영역 섹션들 → 요약 테이블 → foot
- **우측 글랜스 레일 필수**: 요약 + 먼저!(→`#p0`, P0 항목은 `#iNN`) + 유형별 집계 + 약속(→`#s1`). 블록 아이콘은 **Font Awesome**(`fa-thumbtack`/`fa-fire`/`fa-tags`/`fa-handshake`, 이모지 금지). `.gb-count`·유형 집계가 본문 실제 수와 일치
- 모든 앵커(`#p0`, `#sN`, `#iNN`, `#sum`) 유효, toc·sec-cnt 건수 정확
- 필터 버튼 건수 = data-type 실제 집계, 필터·폭 토글(1440↔1920)·**글랜스 토글**·스크롤 탑 스크립트 포함

## B8. 디자인 시스템 준수
- `:root` 변수·클래스가 `template-review.html` 과 일치, 팔레트 외 색 없음
- 전체 border + 옅은 배경 (한쪽 border accent 금지)
- 자체완결 단일 HTML (Font Awesome CDN 만 예외), **아이콘은 `fa-solid`, 이모티콘 금지**

## B9. 콘텐츠 정확성
- 히어로 메타(일시·대상·항목수·목표) 정확, **항목수 일치** (메타 = 필터 전체 = 요약 테이블 행수 = 글랜스 유형 집계 합)
- 항목 내용이 전사 발언과 부합 (왜곡 없음), 숫자·화면명 정확
- 화자 실명 미표기

## B10. 완성도
- `{{placeholder}}`/빈 행·빈 이미지 없음, 캡쳐 없는 항목은 figure 자체가 없음
- 요약 테이블 전 항목 수록 + 앵커 동작, HTML 엔티티 이스케이프
- 렌더 검증에서 레이아웃 깨짐 없음

# Reviewer 출력 형식 (두 모드 공통, 필수)

```markdown
## 평가 결과 (Mode A|B)

| # | 기준 | 점수 | 비고 |
|---|------|------|------|
| 1 | (기준명) | XX | 간단한 평가 코멘트 |
| … | … | … | … |

**평균 점수: XX.X / 100**
**합격 여부: PASS / FAIL**

## 개선 피드백 (95점 미만 항목)

### [기준명] (현재 XX점 → 목표 95+)
- 문제: [구체적 위치와 내용 — 몇 번째 섹션/항목의 어떤 요소인지]
- 개선 방안: [어떻게 수정해야 하는지]
```

**주의:**
- 점수는 정수, 평균은 소수점 첫째 자리
- A9 가 N/A 면 9개 평균
- 95점 이상 항목에는 피드백 작성하지 않음
- "좋음/부족함" 같은 모호한 평가 금지 — 위치·요소 특정
