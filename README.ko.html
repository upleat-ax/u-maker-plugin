WHY U-MAKER

이 플러그인이 해결하는 문제

u-maker는 문서 중심 개발(SSoT)을 강제하는 협업 오케스트레이터입니다.

❌ 요구사항과 코드가 따로 놀아 추적 불가
✅ 4-Tier ID(USR→FR→US→FT)로 요구사항~테스트 전 구간 추적
❌ 단계 건너뛰기로 품질 저하
✅ Phase Gate로 전 단계 문서 Final 확인 후에만 다음 단계 진행
❌ 반복적인 수정-테스트 사이클
✅ PDCA Loop 자동화 (최대 10회 반복, 종료 조건 자동 판정)
❌ 기술 스택 규칙 위반
✅ Hook 기반 사전 차단 (CSS-in-JS, Pages Router 등 10개 규칙)
❌ 문서와 코드 버전 불일치
✅ 문서 변경 시 .md + .json 동시 생성
CORE CONCEPTS

Skills, Agents & SSoT

u-maker 플러그인을 이해하기 위해 먼저 Claude의 Skill, Agent, 그리고 SSoT 개념을 살펴봅니다.

🧩

Skill이란?

Skill은 Claude가 특정 작업을 수행하기 위한 전문화된 지침 번들입니다. SKILL.md 파일에 정의되며, 슬래시 커맨드(/skill-name)로 호출됩니다. 각 스킬은 필요한 도구, 참조 문서, 실행 로직을 자체적으로 포함하는 Self-contained 구조입니다.

🤖

Agent란?

Agent는 특정 역할과 전문성을 가진 AI 페르소나입니다. PM, 설계자, 개발자, QA 등 실제 소프트웨어 팀의 역할을 모사하며, 각 에이전트는 담당 Phase에서 독립적으로 문서를 생성하고 코드를 작성합니다.

📐

SSoT란?

Single Source of Truth — 모든 정보의 단일 진실 원천. 요구사항, 설계, 코드, 테스트가 하나의 문서 체계에서 관리되어 버전 불일치와 추적 불가 문제를 근본적으로 해결합니다. u-maker는 .md + .json + .html 3종 동시 생성으로 SSoT를 보장합니다.

Skill Structure (Self-contained Pattern)

SKILL.md (frontmatter) 
---
name: u-skill-srs
description: |
  SRS generation/update (FR+NFR → US → FT)
  Triggers: /u-skill-srs, SRS
model: sonnet
user-invocable: true
argument-hint: "[app]"
allowed-tools:
  - Read, Write, Edit, Glob, Grep, Bash
imports:
  - ${PLUGIN_ROOT}/_refer/ssot-standard.md
  - ${PLUGIN_ROOT}/_refer/post-execution-summary.md
agents:
  - u-maker:u-agent-ra
  - u-maker:u-agent-sa
---
💡
각 스킬은 필요한 _refer/ 문서만 import하고, 직접 사용할 agent를 선언합니다. 명령당 약 ~11K 토큰으로 경량화되어 있습니다.

Skill 정형화된 호출

  • 슬래시 커맨드로 실행
  • 특정 문서/태스크 단위 작업
  • SKILL.md에 실행 로직이 내장
  • 예: /u-skill-srs web

Agent 자유 형식 요청

  • 자연어로 직접 호출 가능
  • 창의적/탐색적 작업에 적합
  • 역할 기반 전문성 보유
  • 예: /u-agent-sa ERD를 최적화해줘

Phase Gate 상세

Phase담당 Agents주요 활동Gate 조건
PLAN PM, SA, UX Roadmap, SRS (FR→US→FT), IA, Index Roadmap + SRS + IA = Final
DESIGN UX, SA, RA UXGuide, Screen, ScreenFlow, Wireframe, ERD, API, RTM ERD + RTM + UXGuide + API + Screen + ScreenFlow = Final
DO UX, DV-FE, DV-BE Screen 구현, Frontend, Backend, Code Doc, Gap Check bun run build 성공 + Match Rate ≥ 90%
CHECK QA TC 설계, 실행 (Vitest+Playwright), 결함 분석 Critical/Major = 0, 모든 FT 구현, Build OK
ACT RA, PM Backlog 정리, Archive, Retrospective, Daily Report Log + Retro 완료
⚡
Inner Gap Loop: DO Phase 완료 후 Match Rate < 90%이면, Gap FT별로 증분 재실행합니다 (최대 maxGapRetries, 기본 3). 전체 재작성은 금지됩니다. 이력은 3_Code_DV.md에 기록됩니다.

루프 종료를 위해 모든 조건이 충족되어야 합니다:

문제 해결

자주 발생하는 문제와 해결 방법입니다.

배포 후 명령어가 안 보일 때
  1. ./deploy_local.sh --check 실행
  2. Claude Code 재시작
  3. ~/.claude/plugins/cache/u-maker/ 확인
  4. ~/.claude/skills/u-maker__* 심볼릭 링크 확인
문서 작성이 차단될 때

PreToolUse 또는 Docs-First guard에 의한 차단. /u-skill-us-add, /u-skill-fr-add, /u-skill-srs 등 문서 스킬을 먼저 실행하세요.

Build gate 실패 시 
/u-skill-build                      # 빌드 로그 확인
/u-agent-dv-fe 빌드 에러 수정해줘   # FE 수정
/u-agent-dv-be 빌드 에러 수정해줘   # BE 수정
다중 앱 문서 경로가 꼬일 때

.u-maker/u-maker.config.json의 techStack.monorepo.structure.apps 확인. /u-skill-xxx <app> 형태로 명시적 호출하세요.

루프가 무한 반복될 때

최대 반복 제한 (기본 10회)에 도달하면 자동 종료. pdca.maxIterations 값을 .u-maker/u-maker.config.json에서 조정하세요.

Gap Loop가 수렴하지 않을 때

maxGapRetries (기본 3회) 재시도 후 강제 진행. pdca.gapThreshold (기본 90%)와 pdca.maxGapRetries 값을 설정에서 조정하세요.
